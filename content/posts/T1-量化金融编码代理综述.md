# Agenthon 2026 · Track 1 综述：量化金融编码代理（Quant-Finance Coding Agents）

> 课题组内部学习笔记 / 技术博客 · 主题：可验证 AI 在量化金融中的应用
> 竞赛：Agenthon 2026（NeurIPS 2026 Competition Track，agenthon.net）
> 本文对应 **Track 1 — Coding**，动词是 *solve*。

---

## 零、一句话概括

Track 1 考的不是"能不能写代码"，而是**"能不能在沙盒里、靠一次尝试（pass@1）、写出既通过 pytest 单元测试、又满足金融领域不变性约束（no-arbitrage / 守恒律 / 边界条件）的正确代码"**。这是"代码生成能力 × 领域知识 × 可验证性"三重叠加的难题——排行榜头部得分只有 **0.1786**（约 5/28 通过），说明当前最强的通用编码代理在真正的量化金融任务上**远未解决**。

---

## 一、任务解读：T1 到底在考什么

### 1.1 官方设定（已核实）

| 维度 | 内容 |
|---|---|
| 提交物 | Docker 化 AI 代理（打包成 ZIP 上传） |
| 运行环境 | 沙盒容器，无通用互联网；可通过受限连接调用 **House Nemotron**（NVIDIA 提供的受限 LLM 服务） |
| 主指标 | **pass@1**（T1 明确"不带置信区间"，即一次尝试通过率） |
| 准入门控 | **pytest + financial invariants**（单元测试 + 金融不变性检查） |
| 排行榜 | 61 支队伍进入决赛，前 5 名并列 **0.1786**（按上传时间早者胜出），尾部 13 支队伍 **0.0000** |

竞赛规则页把门控拆成统一的 **g0–g3** 四层：
- **g0 完整性**：ZIP 结构、代理镜像可识别；
- **g1 模式/接口**：schema、队伍注册凭证；
- **g2 截止/资源**：无网沙盒、资源上限、as-of cutoff；
- **g3 领域语义**：T1 专属的 **pytest + 金融不变量** 检查。

只有全部四层门控"可受理"（admissible）的运行，其 pass@1 才被计分。

### 1.2 任务原型（task archetypes）

官网给出的 T1 任务原型很能说明"金融不变量"的含义，例如：
- **期权 Put-Call Parity 前向审计**：任何正确的欧式期权定价实现，必须在数值容差内满足 `C − P = S − K·e^(−rT)`——这是一个**与实现路径无关**的无套利恒等式，可作为"测试预言（test oracle）"。
- **方差互换（variance swap）复制**、GARCH-VAR、Copula 拟合、hazard rate、OU 过程等。

关键洞察：**pytest 检查"输出对不对"，而金融不变量检查"解在领域语义上成不成立"**。后者恰恰是 LLM 最容易违反、也最难通过背题蒙混的部分——因为不变量是"性质（property）"而非"具体数值答案"。

### 1.3 为什么这么难（0.1786 的含义）

头部得分 ≈ 18%，可以拆成两重难度：
1. **领域知识门槛**：量化金融代码要同时掌握随机过程、数值方法（蒙特卡洛 / 有限差分 / 树方法）、以及具体金融库（QuantLib、NumPy/SciPy）的 API 语义。
2. **验证门槛**：pass@1 + 不变量意味着"不能靠多采样蒙对、不能靠模式匹配背题"。这与后文 §3 会提到的 **SWE-bench 污染问题**、**"运气通过"（Lucky Pass）问题** 一脉相承——Agenthon 用 sealed 私有考试仓 + canary 审计 + 金融不变量，专门堵住这些漏洞。

## 二、技术方向地图

我把 T1 涉及的技术拆成五个子方向，它们从"通用"到"金融专用"逐层收窄，也恰好对应了研究成熟度从高到低的梯度。

```
(a) 代码 LLM 与编码代理  ← 通用、成熟度最高
        │
(b) pass@1 与测试时扩展（test-time scaling）  ← 通用、快速演进
        │
(c) 金融/科学计算领域代码生成  ← 领域、benchmark 2026 年才出现
        │
(d) 不变性检查与程序验证  ← 交叉、"金融不变量作 oracle"仍是空白
        │
(e) 沙盒代理基础设施与可验证评估  ← 工程、竞赛级防泄漏评估
```

### 子方向 (a)：代码 LLM 与编码代理

从"一次生成代码"到"自主探索代码库、执行、迭代修复"的代理化演进。

**代表工作：**
- **SWE-bench**（Jimenez et al., 2023, ICLR 2024, [arXiv:2310.06770](https://arxiv.org/abs/2310.06770)）：2,294 个来自真实 GitHub issue/PR 的软件工程任务，用 FAIL_TO_PASS / PASS_TO_PASS 测试执行评分。发布时最强模型仅解决 1.96%——奠定了"用真实测试执行来客观衡量编码代理"的范式。
- **SWE-agent**（Princeton, NeurIPS 2024, [arXiv:2405.15793](https://arxiv.org/abs/2405.15793)）：提出 **Agent-Computer Interface (ACI)**——像人类用 IDE 一样，为 LLM 代理专门设计文件编辑、仓库导航、测试执行接口，把 SWE-bench 提到 12.5% pass@1。
- **OpenHands**（原 OpenDevin，Wang et al., 2024, [arXiv:2407.16741](https://arxiv.org/abs/2407.16741)）：MIT 开源的通用编码代理平台，能写代码、跑 shell、浏览网页，跨 15 个任务评测。
- **AutoCodeRover**（Zhang et al., ISSTA 2024, [arXiv:2404.05427](https://arxiv.org/abs/2404.05427)）：以 AST/类-方法结构做上下文检索 + 频谱故障定位，SWE-bench Lite 19%、单例成本 $0.43。
- **Agentless**（Xia et al., ICLR 2025, [arXiv:2407.01489](https://arxiv.org/abs/2407.01489)）：反"复杂代理"路线——简单的"定位→修复→补丁验证"三阶段流水线，SWE-bench Lite 32%、成本 $0.70，反而超过当时所有开源代理。**启示：T1 这种任务边界清晰、无需大范围仓库探索的场景，简单流水线可能比重型代理更稳。**
- **CodeAct**（Wang et al., ICML 2024, [arXiv:2402.01030](https://arxiv.org/abs/2402.01030)）：用可执行 Python 代码作为统一动作空间，比 JSON/文本动作成功率高至多 20%。

**工业产品（无同行评审论文，谨慎引用）**：Devin（Cognition AI, 2024，自报 SWE-bench 13.86%）、Claude Code / Claude Agent SDK（Anthropic, 2025，开源内部 harness）。这些是产品发布，数字为厂商自报、不可独立复现，学习笔记里应明确标注。

### 子方向 (b)：pass@1 与测试时扩展（Test-Time Scaling）

T1 主指标是 **pass@1**（而非 pass@k），这把"能不能蒙对"排除掉，逼出"第一次就写对"的确定性能力。这一子方向研究如何**在推理期投入更多算力**来提升单次正确率。

**pass@k 指标的源头：**
- **HumanEval / Codex**（Chen et al., 2021, [arXiv:2107.03374](https://arxiv.org/abs/2107.03374)）：定义 pass@k（k 次采样中至少一次通过测试的概率）。这是所有后续测试时扩展工作的度量基石。

**自我纠错 / 迭代精化：**
- **Self-Debug**（Chen et al., NeurIPS 2023, [arXiv:2304.05128](https://arxiv.org/abs/2304.05128)）：用执行结果做反馈迭代调试，"rubber-duck debugging"（逐行自我解释后再改）。
- **Self-Refine**（Madaan et al., NeurIPS 2023, [arXiv:2303.17651](https://arxiv.org/abs/2303.17651)）：同一 LLM 兼任生成器/批评者/精化器，7 个任务上绝对提升 ~20%。
- **Reflexion**（Shinn et al., NeurIPS 2023, [arXiv:2303.11366](https://arxiv.org/abs/2303.11366)）：把失败经验写成"语言化自我反思"存入记忆，HumanEval 达 **91% pass@1**（当时 GPT-4 为 80%）——无需梯度更新的试错学习。

**执行反馈 / 生成测试选择：**
- **CodeT**（Chen et al., ICLR 2023, [arXiv:2207.10397](https://arxiv.org/abs/2207.10397)）：让同一模型既生成代码又生成测试，用"双重执行一致性"选最优，HumanEval pass@1 提到 65.8%。**这个"LLM 生成测试当自选择预言"的思想，和金融不变量当 oracle 高度同构。**

**大规模采样 + 过滤：**
- **AlphaCode**（Li et al., *Science* 2022, [arXiv:2203.07814](https://arxiv.org/abs/2203.07814)）：每题采样 ~100 万候选程序，执行过滤 99%，再按行为聚类，Codeforces 达中位水平。**AlphaCode 2**（DeepMind 技术报告, 2023-12）基于 Gemini Pro，解决 ~43% 竞赛题。（注意：AlphaCode 2 只是技术报告，非 Nature 论文，引用需修正。）

**显式测试时计算扩展：**
- **Scaling LLM Test-Time Compute**（Snell et al., DeepMind, 2024, [arXiv:2408.03314](https://arxiv.org/abs/2408.03314)）：证明小模型 + ~10 秒"思考"可胜过 14× 大的模型，提出按题目难度自适应分配算力——这是 OpenAI o1 的学术表述。
- **o3 / o4-mini**（OpenAI, 2025）：把大推理预算用于 agentic SWE-bench，刷新 SOTA。
- **CodeMonkeys**（Stanford, 2025, [arXiv:2501.14723](https://arxiv.org/abs/2501.14723)）与 **S\***（NovaSky AI, 2025, [arXiv:2503.23803](https://arxiv.org/abs/2503.23803)）：并行采样 + 自审 + 多代理辩论的混合测试时扩展框架。

**对 T1 的启示**：pass@1 的天花板取决于两件事——(1) 单次推理质量（推理模型 o1/o3 风格），(2) 推理期能否用**执行反馈 + 生成测试自选择**逼近"确定正确"。但 T1 的 pass@1 是"一次尝试、不许 k 次采样投票"，所以 Self-Refine/Reflexion 这类**单轨迹内迭代**比 AlphaCode 式**多轨迹采样**更契合赛制。

### 子方向 (c)：金融 / 科学计算领域代码生成

这是 T1 与通用编码代理的**分水岭**：领域代码。一个关键发现是——**专门的量化金融代码生成 benchmark 直到 2026 年才出现**，此前金融 LLM 评估几乎全是 NLP/QA 导向。

**科学/数值代码 benchmark（谱系）：**
- **DS-1000**（Lai et al., ICML 2023, [arXiv:2211.11501](https://arxiv.org/abs/2211.11501)）：1,000 道数据科学代码题，覆盖 NumPy/Pandas/SciPy/PyTorch 等 7 个库，用扰动防背题。
- **SciCode**（Tian et al., 2024, [arXiv:2407.13168](https://arxiv.org/abs/2407.13168)，注意 ID 常被误引为 2407.13131）：科学家策划的 338 个子问题、跨 16 个自然科学子领域；Claude 3.5 Sonnet 在最真实设定下仅解 **4.6%**——科学编码仍是硬前沿。
- **SciBench**（Wang et al., 2023, [arXiv:2307.10635](https://arxiv.org/abs/2307.10635)）：大学理科题，最佳仅 43.22%。

**金融领域 LLM 与 benchmark：**
- **BloombergGPT**（Wu et al., 2023, [arXiv:2303.17564](https://arxiv.org/abs/2303.17564)）：50B 参数、363B 金融 token，首个金融领域大模型；但闭源、面向 NLP 而非代码。
- **FinGPT**（Yang et al., 2023, [arXiv:2306.06031](https://arxiv.org/abs/2306.06031)，常被误引为 2306.04991）：开源金融 LLM 全栈框架，LoRA 微调 <$300。**FinGPT-Forecaster**（[arXiv:2402.03659](https://arxiv.org/abs/2402.03659)）能做可解释股价预测，但后续工作（Golden Touchstone, [arXiv:2411.06272](https://arxiv.org/abs/2411.06272)）明确指出其**数值计算能力弱**——恰是量化代码任务的核心短板。
- **中文金融评测**：FinEval / FinEval-KR（[arXiv:2506.21591](https://arxiv.org/abs/2506.21591)）、CFLUE（ACL 2024, [arXiv:2405.10542](https://arxiv.org/abs/2405.10542)）、BizFinBench（[arXiv:2505.19457](https://arxiv.org/abs/2505.19457)）——均为知识/QA 导向，非代码生成。

**量化金融代码生成 benchmark（2026 年才出现，重点）：**
- **QuantEval**（Kang et al., 2026, [arXiv:2601.08689](https://arxiv.org/abs/2601.08689)）：1,575 个专家校验实例，三维度含**量化策略编码**——用确定性 CTA 回测框架执行模型生成的策略、按风险-收益指标对比专家参考（非语法匹配）。评测 13 个 LLM，与人类专家差距显著。**这是与 T1 最接近的现存 benchmark。**
- **Quant-Arena**（2026, [arXiv:2610.30113](https://arxiv.org/abs/2610.30113)）：端到端评测——LLM 代理写策略、构特征、跑回测，在封存的 2024 A 股数据上评估；无一模型跑赢等权基准（GPT 类最佳 10.7% 年化 vs 市场 17.1%）。
- **QuantCodeEval**（OpenReview/SSRN，arXiv ID 未核实）、**ALPHAQT-BENCH**（CityU，ID 未核实）、**FinMathBench**（AAAI，ID 未核实）：策略代码复现、公式-代码 gap、金融数学推理等互补方向。
- **QuantitativeFinance-Bench (QFBench)**（Siqiao Zhao et al., qfbench.com）：Agenthon 2026 收录海报，87 个任务（Black-Scholes、hazard rate、OU、GARCH-VAR、swaption、copula），pass@1 最佳 **61.7%**，Docker 沙盒数值执行 + "Finance-Zero Rule" 基线。（注：QFBench 公开页未明确提"无套利不变量"作验证机制，这一点与 T1 门控不同，引用时应区分。）

**QuantLib 与数值金融代码**：QuantLib（Ballabio 维护，C++ + Python 绑定）提供解析定价、树/格子、有限差分、蒙特卡洛框架（`McSimulation`、`GeneralizedBlackScholesProcess`）。**但"LLM 生成 QuantLib 定价代码"至今几乎无同行评审研究**——检索只返回中文教程（知乎/CSDN）。这本身是一个重要的**研究空白**信号。

### 子方向 (d)：不变性检查与程序验证

T1 门控的第二半"financial invariants"，技术上属于**测试预言问题（oracle problem）**：当你没有标准答案时，靠什么判断代码对不对？答案是靠"性质"。

**基于属性的测试（Property-Based Testing, PBT）：**
- **Hypothesis**（MacIver，开源库，非论文）：Python 版 QuickCheck，用 `@given` 声明性质、自动大量生成随机/边界输入、失败时自动 shrink 到最小反例。**这是把 put-call parity、资金守恒编码成可执行检查的最直接工程手段。**

**蜕变测试（Metamorphic Testing, MT）：**
- **Xie et al., ICSE 2011**（"Testing and Validating ML Classifiers by Metamorphic Testing"）：无直接 oracle 时，定义**蜕变关系（MR）**——如"打乱训练样本顺序不应改变预测""特征缩放应产生可预期的输出变化"——跨多次执行检查其成立。这是 MT 用于 ML 的奠基工作。
- **METTLE**（Xie et al., 2018, [arXiv:1807.10453](https://arxiv.org/abs/1807.10453)）：把 MT 扩展到无监督学习（聚类），oracle 问题更尖锐。
- **Metamorphic Testing of a Deep Learning based Forecaster**（Dwarakanath et al., 2019, [arXiv:1907.06632](https://arxiv.org/abs/1907.06632)）：对真实深度学习预测系统定义 MR，发现传统 oracle 抓不到的缺陷。

**LLM 生成测试/不变量：**
- **CodaMosa**（Lemieux et al., ICSE 2023）：SBST（搜索式测试）遇到覆盖率瓶颈时，用 Codex 提议候选测试输入再由 SBST 精化，41 个 Python + 16 个 Java benchmark 上显著提升覆盖率。
- **TestGen-LLM**（Schäfer et al., Meta, 2023, [arXiv:2302.06527](https://arxiv.org/abs/2302.06527)）："Assured Offline LLMSE"——只接受能构建、通过、且**提升覆盖率**的测试，杜绝幻觉测试；Meta 工程师 testathon 接受率 73%。首个工业级带保证的 LLM 测试部署。
- **LLMs as Test Case Generators: Performance Evaluation and Enhancement**（Li et al., 2024, [arXiv:2404.13340](https://arxiv.org/abs/2404.13340)）：批判性反面证据——题目越难，SOTA LLM 生成正确测试越吃力，质量高度依赖 benchmark。
- **AutoFraming**（2026, [arXiv:2610.29046](https://arxiv.org/abs/2610.29046)）：用 LLM + 代码属性图为 C 代码合成 ACSL 框架规约、**循环不变量**、函数契约，84 个函数上 92.9% 成功（超 SOTA 179%）。承接经典 **Daikon** 动态不变量检测器。
- **DRAGO**（2026, [arXiv:2610.22568](https://arxiv.org/abs/2610.22568)）：修复"能跑但语义错"的 LLM 生成规约，用确定性诊断替代无根据的 LLM 自我批评，回归率从 11.8%→1.3%。

**程序验证 + LLM / 神经符号（neurosymbolic）：**
- **AlphaGeometry**（Trinh et al., *Nature* 2024）：神经 LM 提"直觉"（辅助构造）+ 符号演绎引擎严格验证，IMO 几何 25/30。**"神经假设、符号验证"的经典范式。**
- **AlphaGeometry 2**（2025, [arXiv:2502.03544](https://arxiv.org/abs/2502.03544)）：Gemini-based，符号引擎快 ~300×，84% IMO 几何。
- **AlphaProof**（*Nature* 2025-11, DOI 10.1038/s41586-025-09833-y，**无 arXiv 预印本**，2412.04083 是误引）：3B Transformer + Lean 4 Mathlib 微调 + AlphaZero 式 AND-OR 树搜索 + autoformalization，IMO 2024 银牌（28/42），每步由 Lean kernel 机器检查——**无幻觉的神经符号验证**。
- **Lean Copilot**（Song et al., 2024, [arXiv:2404.12534](https://arxiv.org/abs/2404.12534)）：LLM 原生跑在 Lean 内提供策略建议，74.2% 步骤全自动。
- **DeepSeek-Prover**（Xin et al., NeurIPS 2024, [arXiv:2405.14333](https://arxiv.org/abs/2405.14333)）：大规模合成 Lean 4 证明数据，miniF2F 达 50%。
- **漏洞检测综述**（Tihanyi et al., 2025, [arXiv:2503.10784](https://arxiv.org/abs/2503.10784)）：明确指出 LLM"在 bug 预测和**不变量生成**上有潜力，但缺乏经典方法的形式保证"，主张**混合神经符号**——这正是 T1 门控的理论依据。

**⚠️ 金融不变量作为测试预言——明确的研究空白**：检索 `("put-call parity" | "no-arbitrage" | "conservation") + ("LLM" | "test oracle")` **未找到任何把金融恒等式用作 LLM 代码验证 oracle 的已发表工作**。理论上现成可用的 oracle 包括：
- Put-call parity：`C − P = S − K·e^(−rT)`（与实现路径无关）；
- 无套利/单调性界：`max(S−K,0) ≤ C ≤ S`；call 价格对波动率单调不减；
- 守恒：组合/payoff 模型中总现金流必须对账平衡；
- 对称/缩放：`(S,K)` 翻倍则价格翻倍；路径置换不改变 MC 期望。

CCF ChinaSoft / STVR 2023 蜕变测试专刊明确点名"数字金融"是 oracle 问题重灾区，但**尚无发表的 MC/期权定价 MR 集**。→ **这是本赛道最具原创性的研究机会。**

### 子方向 (e)：沙盒代理基础设施与可验证评估

T1 用 sealed 私有考试仓 + 无网 Docker + canary 审计，本质是**竞赛级防泄漏/防作弊评估**。这一子方向近年因通用 benchmark 被污染而快速升温。

**防污染 / 防泄漏的代码评估：**
- **SWE-bench+**（Aleithan & Haoran, 2024, [arXiv:2410.06992](https://arxiv.org/abs/2410.06992)）：只用训练截止**之后**创建的 issue，消除"解法泄漏"——原 SWE-bench 中 32.67% 的成功补丁涉及泄漏、31.08% 测试太弱。SWE-Agent+GPT-4 骤降到 **0.55%**，揭示此前数字被严重高估。
- **SWE-Bench Pro**（2025, [arXiv:2509.16941](https://arxiv.org/abs/2509.16941)）：1,865 题 + held-out（12 仓）+ 商业私有集（18 个不可公开访问的专有仓），pass@1 稳在 45% 以下，对抗 Verified 的饱和。
- **SWE-Bench Pro V2**（2026-10, [arXiv:2610.24206](https://arxiv.org/abs/2610.24206)）：限制网络仅到模型端点 + 干净容器重新评分，代理无法检索上游修复——**与 Agenthon 的 sealed-Docker、无网设计直接同源。**
- **LiveCodeBench**（Jain et al., 2024, [arXiv:2403.07974](https://arxiv.org/abs/2403.07974)）：持续采集 LeetCode/AtCoder/Codeforces 新题并打时间戳，只用晚于模型训练截止的题评估；**LiveCodeBench Pro**（[arXiv:2506.11928](https://arxiv.org/abs/2506.11928)）扩到 584 道奥赛题。
- **EvalPlus**（Liu et al., NeurIPS 2023, [arXiv:2305.01210](https://arxiv.org/abs/2305.01210)）：HumanEval+（~80× 更多测试）、MBPP+（~35×），揭示大量"看似通过"的解在更强测试下失败。
- **On Leakage of Code Generation Evaluation Datasets**（Matton et al., EMNLP Findings 2024, [arXiv:2407.07565](https://arxiv.org/abs/2407.07565)）：量化代码测试集泄漏并提出检测方法。
- **SWE-Proof**（2026-09, [arXiv:2609.21190](https://arxiv.org/abs/2609.21190)）：主张 held-out 测试"本质不完整且易被记忆"，用 Benchproofer 把 SWE-bench 转成 500 个**形式化验证**问题。
- **AgentLens**（2026-10, [arXiv:2605.12925](https://arxiv.org/abs/2605.12925)）：发现 SWE-bench Verified 上 **10.7%** 的通过轨迹是"Lucky Pass"（混乱试错 + 回归循环），提出过程级评估区分"原理性解法"。**这解释了为什么 T1 坚持 pass@1 + 不变量，而非宽松的 pass@k。**

**Canary / 污染检测：**
- **SIGIL**（Weinberg, 2026, [arXiv:2606.06502](https://arxiv.org/abs/2606.06502)）：向受保护文本/代码嵌入不可见 canary 序列，用 Neyman-Pearson 成员推断检验；code-pattern canary AUC 0.903，100% 改写下仍 0.864。承接 BIG-bench 的 canary-string 协议——**Agenthon 的"canary registry"即此类机制。**
- **MMLU-CF**（2024, [arXiv:2412.15194](https://arxiv.org/abs/2412.15194)）：无污染多任务评测，闭源测试 + 公开验证分割，GPT-4o 降到 73.4%。

**沙盒基础设施（工业）**：Docker Sandboxes（MicroVM 隔离、自定义网络策略）、Harbor + Docker（每任务独立沙盒跑 Claude Code/Codex/Cursor）、NVIDIA NemoClaw（沙盒化 Nemotron 编码代理）。Agenthon 的 House Nemotron 属于 NVIDIA 更广的 Nemotron 编码代理沙盒栈，但**其背后的确切模型未公开**（标注为不确定）。

## 三、相关研究现状小结

| 子方向 | 代表工作 | 现状判断 |
|---|---|---|
| (a) 编码代理 | SWE-agent, OpenHands, AutoCodeRover, Agentless | 通用仓库级修复成熟；**简单流水线常胜重型代理** |
| (b) pass@1/测试时扩展 | Reflexion(91%), CodeT, Self-Debug, o3, CodeMonkeys | 快速演进；单轨迹迭代契合 pass@1 赛制 |
| (c) 领域代码生成 | SciCode(4.6%), QuantEval, Quant-Arena | **benchmark 2026 才出现**；领域 gap 巨大 |
| (d) 不变量验证 | Hypothesis, MT, TestGen-LLM, AlphaProof | 通用验证成熟；**金融不变量作 oracle 仍空白** |
| (e) 可验证评估 | SWE-bench+/Pro, LiveCodeBench, EvalPlus, AgentLens | 因污染问题快速升温；竞赛级 sealed 评估成主流 |

**贯穿主线**：整个领域正从"追求更高 pass@k 数字"转向"追求**可信、防污染、过程正确**的评估"。Agenthon T1 是这一转向在**量化金融垂直领域**的集中体现——pass@1（不许蒙）+ 金融不变量（领域语义）+ sealed Docker（防泄漏）三管齐下。

## 四、应用成熟度评估

分级：**学术研究 → 原型可用 → 工业早期落地 → 成熟应用**

| 能力 | 成熟度 | 说明 |
|---|---|---|
| 通用编码代理（仓库级 bug 修复） | **工业早期落地** | GitHub Copilot Workspace、Cursor、Devin、Claude Code 已商用；但 SWE-bench 污染揭示真实能力被高估 |
| 测试时扩展 / 推理模型 | **工业早期落地** | o1/o3 已产品化，推理预算换正确率成主流 |
| 科学/数值代码生成 | **原型可用** | SciCode 仅 4.6%，可用但不可靠 |
| **量化金融代码生成** | **学术研究** | 专用 benchmark（QuantEval/Quant-Arena/QFBench）2026 年才出现；QuantLib 代码生成几乎无研究 |
| **金融不变量作验证 oracle** | **学术研究（空白）** | 理论齐备、无发表实现——最大机会 |
| 沙盒 / 可验证评估基础设施 | **工业早期落地** | Docker 沙盒、canary、sealed 评估已工程化 |

**业界动向**：Bloomberg（BloombergGPT、Agenthon 金牌赞助、QFBench 合作）、J.P.Morgan（ABIDES 系列）、NVIDIA（House Nemotron、白金赞助）均在推动"金融 AI + 可验证性"。但需注意：**买方/卖方实际把 LLM 用于生产级量化代码生成的公开证据仍很少**——多停留在研究原型和内部试点，T1 头部仅 18% 正是这一现实的量化注脚。

## 五、趋势展望（可检验判断）

1. **"可验证性"成为编码代理评估的主轴**：pass@k → pass@1 + 形式/不变量门控。预测未来 12-18 个月，主流金融 AI benchmark 会普遍加入"领域不变量"作为准入门控（可用 QFBench/QuantEval 是否新增 invariant 检查来检验）。

2. **金融不变量作为 test oracle 会从空白变成热点**：put-call parity、无套利界、守恒律将被形式化为可执行的蜕变关系集。这是最容易出原创论文的方向（当前零发表）。

3. **神经符号混合用于"认证代码"**：AlphaProof 式"神经假设 + 符号/Lean 验证"会下沉到金融数值代码，产出"带机器检查证明的定价实现"。

4. **简单流水线在边界清晰任务上持续跑赢重型代理**：Agentless 的结论（32% > 复杂代理）会在 T1 类"单文件、明确规约"任务上复现；重型自主代理的优势场景是"大范围仓库探索"，而非"一次写对一个算法"。

5. **防污染成为竞赛标配**：sealed 私有仓 + canary 审计 + 无网 Docker（SWE-Bench Pro V2、Agenthon）会取代公开可爬的 benchmark，AgentLens 揭示的"Lucky Pass"问题推动过程级评估普及。
