# Agenthon 2026 Track 4 综述：证据支撑的预测与忠实推理

> 课题组内部学习笔记 / 技术博客 · 撰写于 2026 年 11 月
> 主题：NeurIPS 2026 Competition Track「Verifiable AI for Quantitative Finance」之 T4 — Explainability
> 官方站点：https://www.agenthon.net/

---

## 引言：为什么金融预测必须"举证"

量化金融里，预测准只是必要条件，不是充分条件。一个给出 0.49 复合分的系统，如果它每条结论都"凭空冒出来"，在监管与合规语境下就毫无价值——甚至会因为引用了未公开信息（未来函数）而被罚到负分。Agenthon 2026 把这件事写进了竞赛规则：Track 4（Explainability）要求参赛 agent 对表格实体做标签 / 数值 / 排名预测，且每个预测必须由一份**冻结证据语料（frozen evidence corpus）**支撑。系统同时评估三件事——**预测准确性、证据质量、推理链质量**，并用一道 **Track 4 composite** 复合分给最终排名。

更有意思的是门控（gate）：T4 的准入门控是 **faithfulness（忠实性）+ embargo（禁运）**。前者要求"引用的证据必须真正支持结论"，后者要求"不得引用未来信息或语料外事实"。从排行榜看，头部 Salt-Lake-Agent 拿到 0.4892，而末位 Garros Solo Lab 拿到 -0.2128——**乱引用会被罚到负分**，这是这类任务最直观的信号。

本文把 T4 还原成一个更通用的研究问题——**attributed / grounded prediction**，梳理 2022–2026 年间的相关技术地图、代表工作、落地成熟度，并给出可检验的趋势判断。所有引用论文均经过检索核实，标题 / 年份 / 编号力求准确；不确定的标注"未核实"或仅给标题与年份。

## 一、任务解读：预测 + 检索证据 + 忠实推理三位一体

### 1.1 这是 "Attributed / Grounded Prediction" 问题

T4 的设定可以拆成三个耦合的子任务：

1. **预测（prediction）**：对表格实体输出 label / value / ranking。这是经典的表格监督学习问题。
2. **归因（attribution / grounding）**：每个预测必须挂靠到证据语料中的具体片段。这与 attributed QA、attributed text generation 同构——输出不仅要"对"，还要"可溯源"。
3. **推理链（reasoning chain）**：从证据到结论的推理过程本身被评估，而不只看终点对错。

这与 RAG（检索增强生成）家族同源，但更严苛：RAG 允许"检索到就用"，T4 要求"检索到的必须真正支持结论，且不能是未来的"。也就是说，T4 = 表格预测 ∩ 归因生成 ∩ 时点纪律。

### 1.2 与既有研究范式的关系

- **与 attributed QA / attributed text generation 的关系**：Rashkin/Bohnet 等人提出的 AttributedQA 把"答案是否被引用文献支持"作为一等公民评估；ALCE 基准则给"生成带引用的文本"提供自动评测。T4 的 faithfulness 门控本质上是把这一套评估逻辑前置为**准入门槛**——不达标直接零分或负分。
- **与事实核查（fact-checking）的关系**：把预测句拆成原子声明、逐条用证据做 entailment 验证，是 FActScore、SAFE 的核心范式。T4 的"引用必须真正支持结论"可视为对每条证据-结论对做细粒度蕴含检验。
- **embargo 对应 point-in-time correctness**：在金融机器学习里这叫"未来函数 / look-ahead bias"。季报披露日 ≠ 报告期，按报告期对齐特征就会泄露未来信息。T4 的 embargo 门控等价于强制"任何被引用的事实，其可获得时间不晚于预测时点"。这是量化研究中久已有之的纪律，但首次被写进 agent 竞赛的门控。

一句话：**T4 把"可验证性"从评估指标升级为准入约束**——不是"解释得好能加分"，而是"解释不忠实 / 引用了未来就出局"。

## 二、技术方向地图

围绕 T4，相关技术可分成六条主线。下面分别给出定位与代表工作。

### (a) 带归因的生成与检索增强

这是 T4 的"生成侧"基础：让模型在生成结论时同步给出引用，并接受引用质量评估。

- **ALCE（Automatic LLMs' Citation Evaluation）**：Princeton NLP 提出的基准，含 ASQA、QAMPARI、ELI5 三个数据集，从 fluency / correctness / citation quality 三维自动评测。配套论文《Enabling Large Language Models to Generate Text with Citations》（Gao et al., 2023，arXiv:2305.14627）系统对比了 inline citation 与 post-hoc citation 两类策略，发现**事后补引用**往往比边写边引更稳定，但引用质量仍显著低于人类。
- **RAG 综述**：Gao 等人《Retrieval-Augmented Generation for Large Language Models: A Survey》（arXiv:2312.10997，2023/2024 修订）梳理了 RAG 的技术树（预检索 / 检索 / 后检索 / 生成），是理解"检索-生成耦合"的最佳入口。
- **Self-RAG**（Asai et al., ICLR 2024，arXiv:2310.11511）：训练单一 LM 学会"按需检索 + 自我批判"，用 reflection token 在检索后、生成后做自我反思，过滤无关段落并校验事实性。思路可直接迁移到 T4——agent 在生成预测后自检"我引用的片段真的支持这个数吗"。

**对 T4 的启示**：inline citation 与 post-hoc attribution 各有取舍；Self-RAG 的"反思 token"机制天然适合做 faithfulness 自检。

### (b) 忠实性 / 归因质量评估

这是 T4 门控的技术内核：如何自动判定"引用是否真的支持结论"。

- **FActScore**（Min et al., 2023，arXiv:2305.14251）：把长文本拆成原子声明，逐条对照可信知识源（如 Wikipedia）打分，输出 factual precision。已成为事实性评估的事实标准。后续工作（如 2024 年《A Closer Look at Claim Decomposition》）指出 FActScore 对**拆分方式敏感**——不同 decomposition 会得到不同分数，错误可能来自评估器而非模型。
- **SAFE（Search-Augmented Factuality Evaluator）**（Wei et al., Google DeepMind, 2024，arXiv:2403.18802）：用 LLM agent 对每个原子事实做多步"生成查询 → 搜索 → 推理是否被支持"。在约 1.6 万条事实上与人类一致率 72%，分歧样本中 SAFE 以 76% 胜率压过人类，成本仅为人工的 1/20。配套发布 LongFact 基准与 F1@K 指标。
- **RAGAS**（Es et al., 2023，arXiv:2309.15217）：RAG 评估的事实标准框架，四大指标——faithfulness（答案是否忠于检索上下文）、answer relevancy、context precision、context recall。其中 **faithfulness** 与 T4 的同名门控几乎是同一概念。
- **ARES**（Saad-Falcon et al., NAACL 2024，arXiv:2311.09476）：用 prediction-powered inference（PPI）做自动 RAG 评估，少量人工标注 + LLM 打分，给出统计严格的置信区间，覆盖 context relevance / answer faithfulness / answer relevance。
- **NLI-based entailment 验证**：更早的摘要事实一致性评估（如 FactCC，Kryscinski et al., 2020，arXiv:1910.12840）用 NLI 模型判断"原文是否蕴含摘要句"，这套思路直接迁移到"证据是否蕴含结论"。AttributedQA（Bohnet et al., 2023，arXiv:2212.08037）则把归因做成分级标签（fully / partially / not supported）+ 可复现的自动评估指标。

**一个值得警惕的陷阱**：2026 年的工作《Precision Is Not Faithfulness》指出，FActScore 这类**只测 precision 的指标会奖励"少说为妙"**——模型靠几乎不输出事实就能拿近乎满分 faithfulness。T4 的 composite 同时评估 recall（预测准确性）+ faithfulness，恰好规避了这一盲区。这也解释了为什么排行榜头部不是 1.0：要同时把 recall 与 precision 拉高极难。

### (c) 表格数据预测模型

这是 T4 的"预测侧"基础。

- **TabPFN v2**（Hollmann et al., *Nature* 2025，DOI:10.1038/s41586-024-08328-6）：基于结构因果模型生成的合成表格数据做 in-context 预训练的表格基础模型。新版支持分类+回归、原生缺失值处理，万行级数据约 2.8 秒推理，在 OpenML 小中规模基准上超越 XGBoost/LightGBM/CatBoost。**关键特性**：in-context learning，无需针对新表训练——这对 T4 的"冻结语料 + 多实体预测"非常契合。
- **CARTE**（Kim et al., 2024，arXiv:2402.16785，Inria）：用图表示表格实体 + Transformer 预训练，跨表迁移**不需要 schema 匹配**，在异构表格集合上预训练后超过强树模型基线。这对 T4 中"表格 schema 不固定"的场景尤有价值。
- **表格基础模型谱系**：TabICL、TabICLv2、TabSTAR（arXiv:2505.18125）、ConTextTab（NeurIPS 2025）、Taffy 等，以及清华团队的 LimiX（2M 参数）。它们在 2025–2026 间快速涌现，表明"表格上的 in-context foundation model"正成为新范式，挑战 GBDT 长期霸主地位。
- **GBDT vs 深度学习**：在表格数据上，XGBoost/LightGBM/CatBoost 长期是强基线；TabPFN v2 等在小数据上首次系统性超越它们，但在大规模表格上树模型仍具竞争力。T4 的实体表往往样本不多，foundation model 路线有优势。

**对 T4 的启示**：纯数值/标签预测可优先用 TabPFN v2 / CARTE 这类 in-context 表格基础模型；但 T4 还要求**为每个预测挂证据**，所以表格模型必须与文本检索 / 引用生成层耦合，单跑表格模型拿不到 evidence 分。

### (d) 表格 + 文本混合推理

T4 的证据语料很可能含表格与文本的混合，需要跨结构推理。

- **HybridQA**（Jiang et al., EMNLP 2020）：首个"表格+文本"多跳问答基准，要求在表格单元与周围段落间交叉引用。
- **FinQA**（Chen et al., EMNLP 2021）：金融报告上的多步数值推理，提供答案 + 完整推导过程，8,281 条专家标注 QA。
- **ConvFinQA**（Chen et al., ACL 2022 Findings）：FinQA 的多轮对话扩展，后续问题依赖前文语境。
- **TAT-QA**（Zhu et al., ACL 2021）：金融报告"表格+文本"混合问答，考数值推理、span 抽取与量级识别（% / 百万等）。

**局限与进展**：2025 年的 FinChain（arXiv:2506.02515）批评 FinQA/ConvFinQA 只验最终答案、不验中间推理步，提出用可执行 Python 代码做符号化 CoT 验证；2026 年的 FinanceComplexQA 指出这些基准只覆盖"部分数值计算"，无法评估分析师级综合推理。AFAC2026 金融长文本 Agent 挑战中，基线仅约 15%，头部方案靠"证据工程"而非朴素检索把准确率拉到 93.5%——说明**混合表文推理在 agent 化后仍是硬骨头**。

### (e) 金融领域的证据式预测 / 可解释 AI

把可解释性放进金融监管与现实落地的语境。

- **BloombergGPT**（Wu et al., 2023，arXiv:2303.17564）：500 亿参数金融 LLM，在 FinPile（363B 金融 token）+ 345B 通用 token 上训练。在金融 NLP 五大任务（信息抽取、情感分析、信号判断、分类、信用风险评估）上显著优于同期通用模型，但**未公开发布**，且可解释性仍是短板。
- **FinGPT**（Yang et al., 2023，arXiv:2306.05443）：开源金融 LLM 路线，主打"开源金融"，降低门槛，核心难题被指出是**如何融合金融数据的时序性与 LLM**。
- **摩根士丹利 × OpenAI**：2023 年 3 月宣布合作，9 月 "AI @ Morgan Stanley" 全面上线 1.6 万名投顾，本质是**对自有研报知识库做 RAG**，强调合规护栏与人工复核；2024 年 10 月扩展为 AskResearchGPT 覆盖研究流程。这是迄今最具标志性的"高合规行业 + GPT-4 + RAG"生产级部署。
- **监管侧的可解释性要求**：
  - **SR 11-7**（Fed/OCC, 2011）是模型风险管理（MRM）15 年的"操作手册"，要求模型可理解、可验证、可文档化。**2026 年 4 月被 SR 26-2 取代**，新版在保留核心要求的同时显式回应 AI 时代（含 agentic AI）挑战。
  - **EU AI Act** 采用风险分级，金融信用评估 / 保险定价等被归入 high-risk，强制要求透明、人工监督、文档与日志。
  - **BIS/FSI 2025 论文**《Managing explanations: how regulators can address AI explainability》直接讨论监管者如何处理金融 AI 的可解释性。
- **XAI in finance**：可解释信用评分（SHAP/LIME 在信用模型上的应用）、反洗钱异常归因、因子归因等已有大量工业实践，但多为**事后解释**而非**事前归因**——T4 要求的"预测同时给出证据"比传统 XAI 更前移。

### (f) 幻觉检测与缓解

T4 的 faithfulness 门控本质上是在防"证据幻觉"——引用了不存在或不支持的证据。

- **原子化验证范式**：FActScore / SAFE / HallDetect（2026）等共享同一思路——拆原子声明 → 逐条验证 → 不对称打分（一条被反驳即整体降级）。
- **self-consistency / 约束解码**：多次采样取一致结论降低幻觉；知识约束解码（如 Knowledge-Constrained Tree Search，arXiv:2310.09044）在解码时强制只生成被知识库支持的 token。
- **self-critique**：Self-RAG 的反思 token、以及 "Did the Model Use That?"（2026，arXiv:2610.35295）用 counterfactual 训练提升模型自归因准确性——让模型诚实地说"我到底用了哪条证据"。
- **embargo 视角的幻觉**：引用了未来信息是一种特殊的"事实幻觉"——内容可能为真，但时点不合法。这需要专门的时点校验层，而非通用幻觉检测器。

## 三、应用成熟度评估

按"学术研究 → 原型 → 早期落地 → 成熟"四级评估各子方向。

| 子方向 | 成熟度 | 评估依据 |
|---|---|---|
| 归因生成（ALCE / inline citation） | 早期落地 | 摩根士丹利 AskResearchGPT 已生产级 RAG，但 citation 质量仍低于人类 |
| 忠实性评估（FActScore / SAFE / RAGAS） | 学术研究 → 原型 | 指标成熟、工具链完备，但 precision-only 盲区、分解敏感性仍在被修正 |
| 表格基础模型（TabPFN v2 / CARTE） | 早期落地 | Nature 发表、sklearn 兼容、工业可调用；大规模表格上仍待验证 |
| 表文混合推理（FinQA/TAT-QA 族） | 学术研究 | 基准饱和度低，agent 化方案头部仍依赖重度证据工程 |
| 金融证据式预测 / 可解释 | 早期落地 | 监管框架（SR 26-2 / EU AI Act）就位，但"预测+归因+时点"联合系统仍是新事物 |
| 幻觉检测与缓解 | 原型 → 早期落地 | self-critique / 约束解码进入主流框架，但金融级 embargo 校验尚无成熟产品 |

**关键判断**：把 T4 看作整体，它处于"原型 → 早期落地"的过渡带。单点技术（RAG、表格模型、FActScore）都已可用，但**三者的紧耦合 + 时点门控**尚无成熟范式——这正是排行榜头部仅 0.49 的原因：复合分的天花板被三者的联合难度压住，而非任何单点能力不足。

落地参照：
- **金融研报生成**：BloombergGPT（闭源）、摩根士丹利 AskResearchGPT（RAG over 自有研报）证明"grounded 报告生成"可行，但都强调人工复核护栏。
- **投研问答**：RAGAS/ARES 已被多家投研中台用于内部问答质量监控。
- **合规审查**：SR 26-2 / EU AI Act 推动"模型卡 + 证据日志"成为强制项，与 T4 的 reasoning chain 评估同向。

## 四、趋势展望（可检验判断）

1. **可验证性将取代单纯准确率，成为 agent 评估的主轴。** T4 把 faithfulness/embargo 设为门控而非加分项，预示未来 agent benchmark 会普遍采用"不忠实即出局"的硬约束。可验证：2026–2027 年主流 agent 评测应普遍引入 attribution / grounding 门控。

2. **预测与解释将被联合评分，而非分别打分后加权。** T4 的 composite 分说明设计者认识到 recall 与 precision 必须同时拉高；precision-only 指标奖励"少说"的弊端已被 2026 年研究明确揭露。可验证：复合指标会向 F1@K 这类 precision-recall 联合形式收敛。

3. **表格基础模型（in-context）将在中小样本金融预测上常态化替代 GBDT。** TabPFN v2 登 Nature、CARTE/TabICL/ConTextTab 谱系在 2024–2026 快速涌现。可验证：2027 年金融表格预测赛事中 in-context foundation model 路线占比显著上升。

4. **embargo / point-in-time 校验会从"量化研究员的经验"沉淀为标准化评估组件。** T4 首次把它写进门控，配合 SR 26-2 对 AI 时序数据治理的要求，可验证：2026–2027 出现公开的 point-in-time 校验工具与基准。

5. **self-critique / 反思 token 会成为 grounded agent 的标配自检层。** Self-RAG 已示范检索后/生成后自反思；T4 的 faithfulness 门控天然需要这一层。可验证：头部 T4 方案的开源代码（按规则获奖者须公开）应普遍含 self-verification 模块。
